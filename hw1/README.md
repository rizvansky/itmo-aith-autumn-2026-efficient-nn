# HW1. Аналитическая модель CNN

Оценка FLOPs, пиковой памяти, времени и энергии сети из [задания](https://github.com/On-Point-RND/Efficient-Models-course-ITMO-2026/blob/main/home_work_one.md). Вывод формул и допущения: [hw1_handwritten.pdf](hw1_handwritten.pdf).

## Эксперимент

Замеры выполнены 14.10.2026 в Google Colab на Tesla T4 с 14.563 GiB доступной системе памяти. Python 3.13.15, PyTorch 2.11.0+cu130, NumPy 2.1.3, CUDA 13.0, cuDNN 92700, драйвер 580.82.07. Настройки сохранены в `results/environment.json`.

Сеть работает в FP32, `eval()` и `inference_mode()`. ReLU inplace, свертки без bias, Linear с bias. `cudnn.benchmark`, `cudnn.allow_tf32` и `cuda.matmul.allow_tf32` выключены. Входы случайные, обучение не требуется.

Использована сетка из задания: 11 размеров изображения и 12 размеров батча, всего 132 точки. При seed 42 дополнительные размеры получились S = 80, 272, 352, 400 и B = 29, 56, 179. Параметры времени и энергии подбирались на 63 базовых точках; остальные 69 использовались для проверки. FLOPs и память не калибровались.

Перед каждой серией выполнялись 5 проходов и еще 2 секунды прогрева. Время взято как медиана 21 прохода с синхронизацией CUDA, память как абсолютный `max_memory_allocated()` за один проход. Для энергии использован счетчик NVML: три окна не короче 3 секунд, энергия каждого окна делится на число проходов, затем берется медиана. Это энергия всей GPU, без вычитания простоя. Профилировщик запускался отдельно от остальных измерений.

## Запуск

Нужны Python 3.10+ и NVIDIA GPU. Команды выполняются из `hw1`; в Colab перед командами shell ставится `!`.

```sh
python -m pip install -r requirements.txt
python measure.py --output results_new
python calibrate.py results_new
```

Дополнительная проверка OOM:

```sh
python measure.py --memory-fraction 0.20 --output results_oom_new
```

`calibrate.py` подбирает параметры, сохраняет `theta.json` и четыре графика, а ошибки выводит в консоль. Его можно запустить на сохраненном CSV без новых замеров GPU. Существующий CSV измерений не перезаписывается.

## Обсуждение

Счет FLOPs сверток и Linear совпал с PyTorch profiler во всех 132 точках. Использовано соглашение 1 MAC = 2 FLOPs. Арифметика GAP и сложения bias добавлены аналитически; профилировщик их отдельно не проверяет. Сравнения ReLU и MaxPool исключены: они добавили бы около 0.21% к счету. Обмен с памятью этих операций учитывается.

Модель времени складывает постоянные накладные расходы и времена слоев. Для слоя берется максимум затрат на вычисления и обмен с памятью, то есть предполагается их перекрытие. Получено `t0 = 0.417 ms`, эффективные `P = 4.144 TFLOPs/s` и `W = 82.742 GB/s`. По наибольшему слагаемому модели 8 проверочных точек относятся к launch-bound, 61 к compute-bound. Общего memory-bound режима на этой сетке модель не выделила, хотя ReLU и MaxPool относятся к нему по отдельности. Это оценка по модели; независимого послойного GPU-профиля нет.

Средняя ошибка времени на проверке составила 6.75%. Для S = 272, B = 179 измерено 129.321 ms при прогнозе 94.746 ms. Для S = 32, B = 179 получено 2.565 ms вместо 1.750 ms. Разброс этих серий невелик, поэтому одними колебаниями замеров расхождение не объясняется. Постоянные P и W не описывают зависимость скорости от формы тензора, заполнения GPU и выбора алгоритма cuDNN.

Большинство замеров времени стабильны: медианный IQR/median равен 1.12%. Порог 10% превышен у 3 точек, для S = 64, B = 1 он достигает 63.10%. Также у S = 32, B = 29 медиана серии 0.974 ms заметно выше времени прохода в энергетических окнах, около 0.578 ms. Эти точки оставлены в расчете ошибок.

Память предсказана хуже: MAPE проверки равна 37.83%, во всех точках формула занижает пик. Для S = 80, B = 1 получилось 23.55 MiB вместо 4.38 MiB, для S = 272, B = 179 получилось 1923.74 MiB вместо 862.78 MiB. Формула учитывает веса, вход и живые активации, включая int64-индексы MaxPool. Workspace cuDNN, служебные выделения и округление аллокатора в нее не входят. Их вклад отдельно не измерялся. Эмпирическая поправка не вводилась: по условию память не должна зависеть от калибровки.

Энергия предсказывается с MAPE 6.16%. Медианный CV трех окон составляет 1.58%, максимальный 3.60%. В прогнозе используется рассчитанное время, а не измеренное. Признаки времени, FLOPs и трафика сильно связаны, число обусловленности матрицы около 696. Поэтому нулевой коэффициент при трафике нельзя трактовать как отсутствие затрат на память, а коэффициент при времени как мощность простоя. Модель передает общий рост времени и энергии, но не все особенности отдельных конфигураций.

## Проверка OOM

В основном запуске максимальный пик составил 4.263 GiB при бюджете не менее 14.395 GiB, поэтому OOM не возник. Дополнительно установлен лимит аллокатора 20% через `torch.cuda.set_per_process_memory_fraction()`, что соответствует 2.913 GiB. CSV и настройки этого запуска сохранены в `results_oom/`.

| S | B | Прогноз памяти, GiB | Бюджет, GiB | Результат |
|---:|---:|---:|---:|---|
| 512 | 179 | 2.976 | 2.913 | OOM |
| 512 | 256 | 4.254 | 2.913 | OOM |

Оба OOM предсказаны формулой, остальные 130 точек прошли. Это OOM при искусственном ограничении аллокатора. Совпадение на этой сетке не гарантирует точную границу для других лимитов: workspace и резервирование блоков могут вызвать ошибку раньше прогноза памяти тензоров.
